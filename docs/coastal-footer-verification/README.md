# Coastal footer — интеграция в основной сайт

Проверено 31 октября 2026 года. ASCII-сцена подключена после `<main>` через общий `DocumentLayout.astro` и отображается на главной, в статье и обоих кейсах. Отдельный корневой `index.html` удалён. Генерируемый `dist/index.html` остаётся главной страницей сайта.

## Структура

- `src/components/CoastalFooter.astro` — общий футер с Canvas и локальными стилями, без видимого текста, ссылок и кнопок.
- `src/scripts/coastal-footer.ts` — небольшой загрузчик. Динамически импортирует рендерер при приближении футера на 240 px к экрану.
- `src/scripts/coastal-world.js` — перенесённый процедурный рендерер. Статическая геометрия и глифы кешируются; период анимации — 24,5 секунды.

Цвет фона читается из существующего `--color-background-1`: белый в светлой теме, чёрный в тёмной. Футер не изменяет стили `<html>`, фон, шрифты или метаданные остального сайта. На мобильных высота сцены составляет 360–480 px. Анимация останавливается вне экрана и при скрытии документа. Reduced motion показывает неподвижный кадр; при фокусе на Canvas пробел включает и останавливает движение. При отключённом JavaScript декоративный футер скрывается, а основной контент остаётся доступен.

## Проверки

- Astro check: 0 ошибок, предупреждений и подсказок.
- Production build: четыре прежних маршрута, без отдельной страницы-прототипа.
- ESLint, Prettier, проверка контента и статического вывода проходят.
- Общий JavaScript production-сборки: 21 360 байт исходного кода / 9 916 байт gzip при лимите 30 720 байт gzip.
- Существующий браузерный набор: 10 комбинаций главной страницы, 20 статьи и 40 кейсов. Проверены контент, изображения, темы, клавиатура, touch, история, отсутствие JavaScript, локальные ресурсы и CLS.
- Отдельная проверка футера: по 48 комбинаций в Chromium 156.0.8078.74 и WebKit 26.5. Четыре маршрута × две темы × ширины 320, 375, 700, 701, 1440 и 1944 px.
- Футер находится после основного контента, занимает ширину страницы, не создаёт горизонтального переполнения и не содержит видимого HTML-текста или элементов интерфейса.
- Проверены отложенная загрузка, живая смена темы, пауза клавиатурой, reduced motion и остановка вне экрана.
- В обоих движках кадры 0 и 24,5 секунды совпадают: ноль различающихся каналов пикселей в обеих темах. Время управляется извне средствами проверки; диагностический API в production не переносился.
- Основной контент сохраняется без JavaScript на всех четырёх маршрутах; декоративный футер скрыт.

Проверки выполнялись на Node.js 24.22.1 прямым запуском установленных CLI из `node_modules`; версии зависимостей, `package.json` и lockfile не менялись. Браузерные проверки выполнялись на локальной production-сборке. Физические телефоны и публикация на Vercel в эту проверку не входили.

## Повторный запуск

После сборки и запуска production preview:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
BROWSER_EXECUTABLE=/absolute/path/to/chromium \
node scripts/verify-coastal-footer.mjs
```

Для WebKit задайте `COAST_BROWSER=webkit` и соответствующий исполняемый файл. По умолчанию адрес preview — `http://127.0.0.1:4321`; его можно переопределить через `VERIFY_URL`.

`chromium-report.json` и `webkit-report.json` содержат результаты проверки футера. В `site-regression/` сохранены результаты существующего набора проверок сайта. PNG показывают арт вместе с соседним контентом и отдельно, в обеих темах на 375 и 1440 px. Папки `docs/coast-verification/` и `docs/coast-art-verification/` относятся к архивным версиям отдельного HTML-прототипа.
